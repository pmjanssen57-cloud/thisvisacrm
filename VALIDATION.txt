THiS CRM v0.17.83 - 10 November 2026

TEMPLATES & BLOCKS ACROSS BOTH STUDIOS
Open Templates & blocks in the Instructions or Agreement Studio toolbar. Master templates, Team blocks and My blocks use the same clean manager, search, rich-text controls and live section preview. Personal blocks are stored against the authenticated adviser account, separately for each Studio, and are available across browsers/devices. The adviser viewing filter does not change library ownership. A login must be linked to an adviser to save My blocks; access-code administrators without an adviser profile can still maintain Team blocks and masters.

MASTER TEMPLATES
Administrators can maintain category-specific starting templates. Instructions includes all guides, cover headings/subtitles, introductions, section wording and order, inclusion defaults, document requests and sign-off defaults. Agreement includes cover/introduction, agreement sections, scope of services, professional payment stages with service links, and office charge/GST/hourly-rate/interest defaults. Existing agreement compliance and issue checks remain in place. No new immigration-policy wording or financial thresholds are introduced.

Edit and save a master draft separately from the published template. Publish requires a review checkbox and change note. Version history retains the most recent 20 published snapshots; Restore into draft does not publish it until explicitly published again. Blocks can be added, duplicated, moved, excluded or removed, and their text, tables, callouts, cards and steps tailored. The preview shows the section; full pagination remains visible in Studio.

Published templates seed new, untouched drafts. If editing has already started while the library loads, the draft is left alone. Existing saved client drafts are never automatically rebuilt. Apply published template is a deliberate, confirmed action for the matching application type. It replaces standard wording/sections while retaining custom reusable sections, client details, named people and existing evidence assignments. Agreement scope/payment replacement clears fee amounts for review and retains client/signature details; issued agreements are locked. Publishing a master does not change the client document from which the manager was opened. Drafts record the applied master version in their existing Studio JSON.

REUSABLE BLOCKS
Advisers can create, preview, duplicate, edit and remove their own reusable blocks. Administrators can maintain shared Team blocks. Team wording can be made into a personal copy. Save reusable block captures the selected client section or introduction; Instructions also supports reusable sign-off settings, and Agreement has Save block actions beside individual services and professional payments. The destination can be My blocks or Team blocks where permitted. Libraries hold up to 100 blocks per scope per Studio.

Formatting is retained, including supported tables, callouts, cards and steps. Instructions document requests use labelled document-name/guidance fields and role checkboxes. Reuse maps those roles to the actual named people, creates fresh request identifiers and leaves assignments editable. Sign-offs keep the real logo and draw adviser name/licence from the client draft. Agreement service and payment blocks insert into their respective lists; payment amounts start blank and service coverage must be reviewed. Recognised client-name/first-name/pathway fields fill when rendered. Agreement snapshots/exports materialise these values so saved client copies remain readable in the preceding renderer.

Saving requires confirmation that client-specific information has been removed. Known client facts are replaced where supported, but the adviser must review titles, text and requests. Inserted blocks are independent copies: later library edits or deletion do not change client documents. Earlier saved wording is retained and can be explicitly imported through Earlier saved wording. It is not silently uploaded. Instructions Add block also lists the new account/team blocks alongside the existing options, including relationship, custody/consent and dependency evidence.

PERSISTENCE AND SCHEMA
No migration or schema change. All 49 previous migrations are byte-identical. New libraries use dedicated rows in the existing instruction_template_library and agreement_template_library JSON tables. Existing master rows and legacy libraries are retained. Personal rows are fetched only through an authenticated, owner-scoped request and are not added to shared bootstrap/cache data. Team/master writes require administrator access server-side. Revision checks prevent silent overwrites by concurrent editors: failed saves keep the editing panel open for copying/reloading. The existing full database backup includes these existing tables and their rows.
