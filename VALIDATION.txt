THiS CRM v0.17.63 — 27 October 2026

All in-app confirmation prompts now use a shared CRM-styled dialog, including the intake results email shown in the reported screenshot. Existing CRM confirmations and former browser confirmations use the same presentation. Existing titles, action labels, explanatory details and Confirm/Cancel outcomes are retained. The intake fallback now forwards the complete confirmation options, including its Email results label and explanatory text.

Replaced 33 browser-confirm call sites across the app, client/calendar navigation guards, intake and employer reviews, side-panel close/discard controls, email template resets, Instructions Studio reset/restore/remove operations, people/document selections and the public live-chat end action. Confirmation is asynchronous: guarded operations wait for the decision. Event values needed after waiting are captured before awaiting. A static source audit finds no remaining native confirm calls in app or public scripts.

The common dialog uses the CRM colours and typography, safe text rendering, keyboard focus trapping, Cancel focus, Escape/backdrop cancellation and focus restoration. Dialog requests are queued. It appears above editors and works on small screens with a scrollable message body and reachable actions. Shared assets are loaded by all local HTML entry points and included in the PWA cache. Browser-required close/reload warnings for unsaved pages remain native because browsers do not allow those warnings to be replaced by an asynchronous application dialog. Informational alerts and input prompts are not confirmation dialogs and were not broadened into this change.

Baseline v0.17.62. Manage client, My Work, enquiry badge/review workflows and queue menu fix retained. No schema changes or new migrations. All 48 migrations and all 24 Netlify modules are byte-identical. Instructions Studio scripts changed only for confirmation handling; the agreement engine is unchanged. Actual sample print comparisons against v0.17.62 passed for both Studios: content, page count and geometry match.

Validation: production build; JSX/JS/public and inline script syntax; CSS/inline styles; undefined-reference checks including the new dialog service; PWA/cache references; migration integrity; ZIP CRC and contents. Explicit tests cover Cancel sending no intake email, Confirm sending exactly one mocked email, dialog layout at 1440/1024/768/390/320px and a 390x420 short viewport, Escape preserving a dirty underlying editor, confirmed/discarded editor closure, Studio person removal and template reset cancellation. No browser-native dialogs occurred in those flows. Manage client draft/save/discard/navigation, enquiry count/review-transition, queue menu, My Work and broader app save/Studio integration regression suites passed.

Limits: local Edge, synthetic data and intercepted APIs; no production data, real emails, live deletes or physical device checks. Every old confirmation call site was audited, but not every conditional UI path was exercised interactively. Print comparisons cover representative samples, not every template combination. Local Node 24; Netlify pins Node 20.19. Existing bundle-size advisory remains.

Deployable source ZIP requires the normal Netlify build. Rollback ZIP is an exact copy of v0.17.62. Nothing deployed.
