# THiS CRM v0.17.77

THiS CRM v0.17.77 — 6 November 2026

INSTRUCTIONS PDF PRINT ROUTE
The supplied THiS CRM.pdf contains 16 physical A4 pages. The content is arranged as eight intended document canvases; alternating pages contain only a cover website/footer or the content-page footer and page number. The defect occurs in the user's CRM print output. Earlier verification covered direct Studio exports and did not adequately exercise the embedded CRM Print button and its resulting print target.

The embedded Instructions Studio Print / save PDF action now opens a dedicated top-level print window containing only the generated document, its existing style sheets and the final print rules. The new capture handler runs after the existing name/person/review guards and stops older bound print handlers from also invoking iframe printing. The existing draft HTML is rendered and inline edits are applied before populating that window. This isolates document pagination from the CRM iframe/outer-page print context and retains a visible Print / save PDF retry button and Close button. The title uses the instruction issue title rather than the CRM application title.

A4 dimensions, zero page margins, no canvas scaling, bounded page heights and explicit page breaks are set in the isolated print context. Content footers are absolutely anchored to their page; cover website text is anchored inside the cover footer. The canvas keeps the existing 296mm height inside A4, with overflow contained. Text shadows are disabled in print to avoid duplicated text extraction from shadowed cover labels. The window waits for style sheets, images and fonts (with a bounded asset wait), reports the logical document page count and opens printing. If the browser blocks the window, Studio gives an explicit instruction to allow it and retry, rather than silently falling back to the old iframe print path.

HOW TO USE
Deploy v0.17.77, reload the CRM to pick up the new PWA version, reopen the instruction draft and use the Studio's Print / save PDF button. Allow the new print window for the CRM site if prompted. Use that document window for printing/saving. The CRM browser menu's Print command is not the document export workflow. The print window's Print / save PDF button allows another attempt without rebuilding the draft. Standalone Studio exports retain their existing route and were regression-checked.

It contains the document and print toolbar only, with the issue title and final A4 rules. It exported three PDF configurations: CSS page size, explicit A4, and explicit A4 with 10mm margins requested through the export API. In all three, eight logical document pages produced exactly eight physical pages. Both cover website lines and all six content-page footers are present on their respective pages; no footer-only or blank pages. The default A4 export was rendered through Poppler, the complete eight-page contact sheet and enlarged cover were visually inspected. The popup-blocked path was also exercised and does not call the iframe print fallback.

The regression suite passes for individual element duplication/reorder/remove/add/styling, sign-off editing and save/reopen, family/person-specific document evidence, rich formatting, library/restore, safe paste, mobile printing access and bounds. All twelve category starters render road map and documentation guides. Direct Studio standard/long-label exports retain bounded A4 covers. Application JSX/JS, all 27 Netlify modules, 11 public scripts, CSS including the new isolated print CSS, inline scripts/styles, PWA/precache references and release versions validated. ZIP CRC, unique/safe paths, all file hashes and exact rollback integrity verified.

DEPLOY / ROLLBACK
Deploy THiS-CRM-v0.17.77.zip using the normal Netlify source build: yarn build, publish dist, functions netlify/functions. No database action required. This source ZIP excludes node_modules and generated dist. Cache version is v0.17.77; the new instructions-print-window.js is included in the precache. Nothing deployed to production.
