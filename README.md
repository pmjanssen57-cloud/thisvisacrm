# THiS CRM v0.17.89

THiS CRM v0.17.89 — 12 November 2026

POST-SEMINAR BOOKING INVITATIONS
In Enquiries > Seminars > Setup, save Presenter email and, optionally, Presenter booking link. The existing presenter name is retained. These details prefill the invitation preview and can be adjusted for a particular batch. Choose Booking invitation on an approved registration, or select one seminar and use Invite approved to book for a bulk invitation. Prepare preview, select recipients, review the subject/extra message and confirm Queue invitations. Emails are available after the saved seminar date/time; this is a manual post-seminar action, not an automatic scheduled marketing email.

The invitation thanks the person for joining and invites them to discuss their situation and next steps with the presenter. It includes the presenter's name and email address. A saved HTTPS booking link produces a Book a time button. Without a booking link, the button opens a message to the presenter to arrange a time. The presenter's address remains visible in the email text and direct email link either way. No attendee address is added to the booking URL. It does not promise a free consultation, price or meeting duration. Messages send from the existing configured CRM Microsoft mailbox; the presenter address is included in the invitation, not substituted as the sending mailbox.

Approved registrations qualify, including archived rows whose archive metadata records a previous Approved status. New, declined and spam entries do not qualify. Duplicate email addresses are combined for sending while original registration records remain separate. The individual action and bulk action share the same recipient protections. Registration approval/archive status is not changed by a follow-up email.

Already-sent, queued, failed or uncertain invitations reserve that email address for that seminar and are excluded from new previews. This prevents overlapping individual/bulk batches or repeated clicks from sending another invitation. A lost response can be retried using the same request key. Preview tokens reject changed settings/recipients. Cancel remaining releases unsent/failed recipients for a fresh preview; sent and uncertain outcomes stay protected. Retry failed invitations retries definite failures only. If saved seminar details change before sending, the batch stops for review. Each recipient receives a separate email and a CRM email log entry (seminar_booking_followup). Sent means Microsoft accepted the send, not guaranteed inbox delivery.

QUEUES / CONFIGURATION
The existing signed seminar background dispatcher sends queued invitations, with up to 20 recipients per batch invocation. The existing five-minute scheduler continues outstanding chunks. Follow-up jobs are separate from pre-event reminder jobs, so closing/archiving a seminar stops its reminders without suppressing post-seminar invitations. Closed seminars and their archived approvals can receive follow-ups. Pending batches can be cancelled; a send already in progress may finish and is treated as uncertain if its outcome cannot be established. Check Microsoft Sent Items and the CRM email log before any manual resend.
Existing Microsoft configuration is reused. SEMINAR_REMINDERS_ENABLED=false stops both existing seminar sending and follow-ups. Optional SEMINAR_FOLLOWUPS_ENABLED=false stops only new follow-up sending/creation/retries; history, previews and cancellation remain available. No new secret or scheduled function is required.
