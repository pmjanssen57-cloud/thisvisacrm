# THiS CRM v0.17.75

THiS CRM v0.17.75 — 5 November 2026

DAILY TEAM OVERDUE EMAIL
At the scheduled 3pm Pacific/Auckland run each day, including weekends, every active adviser with a valid email recorded in Advisers receives the full team overdue-file list. Each address is emailed separately and duplicate addresses are collapsed. Inactive advisers and blank/invalid email addresses are not recipients. Their assigned overdue files remain visible in the full report, along with unassigned files. The report is grouped by main adviser and ordered oldest overdue date first within each group.

The report includes individual and commercial/employer files, client/employer name, matter/category, next action or review, matter status, due/review date and days overdue. The waiting-file review-date preference and action-date fallback match My Work. An overdue date must be strictly before today's New Zealand date. Today/future, Closed and Completed files are excluded; personal tasks and document-expiry reminders are outside this file report. A waiting file is included when its review is overdue regardless of who has the ball. Missing/invalid dates do not become overdue. Everyone receives the same complete team list for that run. A no-overdue-files email is sent when the team is clear. The Open My Work link opens the CRM; users may need to sign in.

SCHEDULE / MAIL
The published Netlify schedule checks UTC hours 02 and 03 at ten-minute intervals. The worker gates on the local Pacific/Auckland hour of 15, handling NZST/NZDT automatically. The first normal tick is 3pm; repeat ticks until 3:50pm recover failed dispatch/token requests and explicit mail rejections, without resending successful recipients. This is a server schedule, independent of whether anyone has the CRM open. Delivery is not guaranteed at the exact second: provider processing and hosting delays apply.

The scheduled entrypoint dispatches an HMAC-signed, short-lived request to the background worker at the production URL so a larger team is not squeezed into the scheduled-function time limit. The worker verifies the signature/date/time before database or email work. It uses the existing Microsoft Graph email credentials and sender settings: MICROSOFT_TENANT_ID, MICROSOFT_CLIENT_ID, MICROSOFT_CLIENT_SECRET, MICROSOFT_NOTIFICATION_FROM_EMAIL (existing fallback THiS@turnerhopkins.co.nz). No new secret or recipient configuration is required. Credentials must be available to Netlify Functions. The runtime URL is used for dispatch and the CRM link; no dependency on build-only CONTEXT/DEPLOY_URL variables. No email is sent from the browser.

Netlify runs schedules automatically only on published deploys. Run now is a real invocation and can send emails during the 3pm window; do not use it as a harmless preview. To disable, set OVERDUE_DIGEST_ENABLED=false for Functions and redeploy. Background functions must be available on the site's Netlify plan, as for the existing background backup capability.

DELIVERY SAFEGUARDS / OPERATIONS
The new daily_overdue_digest_log table has one atomic claim per NZ report date and normalized recipient email. Repeated and concurrent invocations skip Sending, Sent and Unknown rows. Explicit provider rejections can retry on a later tick. Timeouts, network uncertainty, provider 5xx responses or a log-write failure after acceptance are marked Unknown rather than automatically re-sending. If a process terminates during a request, a Sending row remains held. Check sender Sent Items/provider message trace before manually resetting an Unknown or stale Sending row; do not blindly retry them. Sent in the operational table means Microsoft accepted the request (HTTP 202), not a confirmed mailbox delivery receipt. No exactly-once delivery claim is made for the external mail provider.

Netlify function logs show run counts, invalid active email count, failures and uncertain outcomes. The operational table stores date, recipient, file count, attempts, status, timestamps and provider request ID/error; it does not store the report/client contents. No new administration screen or email template editor is added. Existing source data is read only by this feature.

SCHEMA / MIGRATION
One new additive migration: netlify/database/migrations/202611050001_add_daily_overdue_digest.sql. It creates only daily_overdue_digest_log and its primary key/check constraint. The same CREATE TABLE IF NOT EXISTS definition is applied by the first worker run, following the existing reminders' schema-initialization pattern. If your production database user cannot create tables, apply this included migration through your normal database migration process before the first 3pm run. It does not alter clients, advisers, existing email tables or any prior migration. The 48 prior migrations are byte-identical; 49 SQL migration files in total. No production schema was changed by this task.

It includes the new schedule, two function entrypoints, shared digest helper and additive migration. Existing Microsoft settings/database access are reused. Confirm each intended active adviser has the correct email recorded. The schedule starts on the published deployment; no Codex reminder/automation is required. The PWA cache version is bumped to v0.17.75. Existing v0.17.74 investor contact form, redirects, employer questionnaires, My Work, client editing and Studio/PDF improvements are preserved. Nothing deployed to production and no real adviser email was sent during this task.

THiS-CRM-v0.17.74-ROLLBACK.zip is an exact copy of the delivered v0.17.74 release ZIP. Rolling back removes this release's scheduled functions.
