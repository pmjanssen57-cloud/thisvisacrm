THiS CRM v0.17.81 — 9 November 2026

SIMPLER INSTRUCTIONS AUTHORING
Based on v0.17.80, retaining Agreement Studio's application-specific services and the website forms refresh. Instructions Studio now has one optional, collapsible Case details & plan panel. Enter the agreed pathway and the relevant employer, role, qualification and institution once. Category-specific alternatives cover course/provider/funding, investment assets/arrangements, supporting person, or visitor purpose/host. Existing named people and per-document assignments remain in the existing family controls.

Available structured employer/qualification facts provided by the linked CRM record or embedded intake snapshot seed the fields for adviser review; no conclusions are inferred from narrative notes. Imported facts do not automatically change document wording. Advisers can write their professional assessment once in the optional Why this pathway fits field. For SMC and AEWV, choose the employment stage and whether IQA, registration or an interim temporary visa is included.

Build / update draft opens a concrete wording preview and explains which sections will be replaced. Keep current document cancels unchanged. Use this draft updates the standard openings, strategy, category explanation, timeline, employment and next steps together. Four strategy cards and the selected numbered timeline use the same plan. Named qualification/employment guidance is added to the relevant document sections. AEWV qualification information is added while retaining the existing skills guidance. Automatically generated facts are restored to starting wording when a field is cleared; independent manual wording is retained. Pathway names and applicant first names remain consistent across standard wording and covers. Pending case changes are labelled Changes to apply.

The writing uses a warmer client-facing voice: what we will do, what to send and what happens next. Exact dates, pay thresholds, eligibility conclusions and guarantees are not invented. The adviser remains responsible for the selected stages and case-specific advice. Every paragraph, step, card and layout remains editable afterwards. Applying a plan explicitly replaces the standard sections named in the review; custom blocks, family records, document requests and individual person assignments are retained. Existing saved instructions are not automatically rebuilt when opened. Changing category retains basic case facts but clears the old pathway-specific assessment and stage selection for review.

READY-WRITTEN REQUESTS AND REUSABLE WORDING
Common document request opens a small library for passports, full birth records, photos, qualification certificates/transcripts, employment agreements and references. Advisers select actual requests; names and guidance remain editable. Starting assignments use all named people for identity items and the main applicant for qualification/employment items. These are editable starting choices, not automatic determinations of who legally needs a document. Existing country-specific police and medical controls remain unchanged.

Save reusable wording presents a normal rich-text editor, with formatting controls, title and a review checkbox. Known client facts are replaced with reusable placeholders to help remove case information, but the adviser must review the text before saving. Client name/pathway and approved case-detail placeholders fill from the current draft when reused; unfilled saved-wording placeholders block issue/printing until tailored. Save a reviewed generic block personally in this browser, or (for administrators) share it through the existing CRM template library. Non-administrators can use shared items and keep personal items but cannot alter team items. Add block > Saved wording searches/inserts them. Remove saved wording leaves already inserted client documents unchanged. The library holds up to 40 items per scope and asks for removal of an unused item when full, instead of dropping old items silently. Personal items are browser-local; team items use the existing administrator-controlled JSON library. No external drafting service is introduced.

ALTERNATING PDF PAGES
The supplied Danielle PDF was inspected: 16 physical pages, alternating eight content pages and eight footer-only pages. It is retained unchanged as reference material. Prior code used the isolated print document for the embedded CRM button but retained a separate standalone/keyboard/browser-menu path. v0.17.81 unifies Studio Print / save PDF and Ctrl/Cmd+P, embedded or standalone, around the bounded top-level A4 document. The print window carries only controlled document classes, not the editor's split/mobile state. Page, body, cover, content and footer geometry are explicit; footers remain positioned inside each 296mm A4 canvas. Keyboard printing uses the same validation and route. Browser-menu/direct printing of Studio also populates the print root and receives the same bounded footer rules. Print text shadows are removed so text is not duplicated in PDF extraction. A blocked print window reports the problem and does not fall back to the former defective route.

After deployment, reopen an existing saved draft and choose Print / save PDF. No rebuild is needed to obtain the new print layout. Applying a case plan is a separate authoring choice. The original saved Studio JSON for Danielle was not supplied, so testing used a representative family case with similar structure and synthetic employer/qualification details, not a reconstructed or rewritten client document.
