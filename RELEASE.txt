THiS CRM v0.15.16 - Migration Integrity Restoration

Baseline
- Built from v0.15.15 Family Editor Expansion Fix.
- Retains the full v0.15.15 CRM, family editor fix, database-idle optimisations, live chat, intake, portal, Instructions Studio and Agreement Studio functionality.

Migration integrity restoration
- Restores 202608110001_add_intake_updated_at_index.sql byte-for-byte to the original v0.15.12 file that was applied to the database.
- The later v0.15.13 comment-only edit has been removed; the SQL operation itself is unchanged.
- All other historical migration files match the v0.15.12 package, while the legitimate v0.15.14 optimisation remains in its separate 202608170001 migration.

Family editor fix
- Adding a spouse/partner or child now reveals the newly created row inside the client editor's own scroll area.
- The reveal waits for the expanded row layout to settle, keeps the full row above the fixed editor footer and focuses the new member's name field.
- Existing family records, counts, age calculations, removal and save behaviour are unchanged.

Database-idle optimisation
- Public chat availability is served from cached Netlify Blob settings after cache warm-up.
- Closed website widgets do not load the visitor iframe; their lightweight launcher check no longer needs Postgres once the settings cache exists.
- Per-conversation Blob revision markers allow unchanged visitor/adviser chat checks to finish without Postgres.
- Practice-level Blob attention marker tracks waiting/active/unread chat state without querying the conversation tables on every badge check.
- Visitor and adviser clients retrieve only messages/events newer than their existing cursors.
- Chat settings and adviser lookup data are cached outside the transactional query path.
- Chat runtime markers are refreshed after all chat mutations.

Polling behaviour
- Public launcher status checking stops when the page is hidden.
- Visitor message polling stops when hidden.
- CRM chat polling stops when hidden and when the user is logged out.
- Existing schedule-aware sleep remains active outside chat hours when no waiting/active conversations exist.

CRM reference/query optimisation
- Advisers, email templates, Instructions templates, Agreement templates and consultation types are Blob-cached for the main CRM loader.
- Cache entries are invalidated/refreshed by their relevant save/delete actions.
- Routine save/delete actions use targeted responses rather than full CRM reloads.
- Normal CRM/chat query paths no longer use SELECT *.
- Added indexes for high-frequency chat queue/messages and common client stage/deadline/task/calendar/billing lookups.

Database retained from v0.15.14
- Includes migration 202608170001_optimize_idle_runtime_queries.sql.
- Index-only migration; no data transformation.

Provider-side settings
- Keep database sleep-on-inactivity at five minutes.
- If the database plan exposes a compute cap, test a maximum of one or two compute units and retain the lowest setting that provides acceptable performance.
- These two settings are account-side and are not changed by the ZIP.

No new migration, dependency or environment-variable changes.
