WHAT CHANGED
The shared success helper sends the existing THIS_FORM_SUBMITTED event to the trusted website parent when embedded. A single new Squarespace Footer Code Injection snippet opens the matching thank-you page in the website window. It checks the exact CRM origin, sending iframe window, form route, event type/source and submission ID, deduplicates success, and uses fixed destinations. Direct standalone form submissions open the same destination. Unknown form keys are ignored. No names, answers, email addresses, tokens or submission IDs are placed in destination URLs. Feedback now emits a success event as well.

Assessment success reporting now waits until all expected CV uploads finish. A failed upload stays on the questionnaire for retry, preserving its saved receipt and avoiding another questionnaire POST. Failed submissions and draft saves do not redirect. The existing inline confirmation remains available in embedded forms if the Squarespace listener is missing. Booking, payment, chat messages and portal updates are outside these five requested mappings and are unchanged.

INSTALLATION
1. Confirm the five thank-you pages above are published and accessible. The release does not publish or change Squarespace pages.
2. Deploy THiS-CRM-v0.17.71.zip using the normal Netlify build process (yarn build, publish dist).
3. In Squarespace Footer Code Injection, replace any previous thank-you redirect listener with the COMPLETE contents of THiS-Squarespace-Thank-You-Redirects.txt, including its script tags. Install once site-wide. Keep the iframe embed code and its height/resume/scroll handlers. Do not paste this into Custom CSS.
4. Save Squarespace and check one completed test submission per form on the saved public website, desktop and mobile. Assessment must finish its uploads first. Failed saves must leave the form available to retry. Thank-you content should explain the relevant next steps; seminar receipt does not mean an invitation is approved.
5. Use the relevant thank-you URL as the completion destination in your analytics setup. Check existing THIS_FORM_SUBMITTED conversion listeners/goals so that the old submission event and the new thank-you page do not both count the same submission. This release does not install Google tags or configure GA4/Ads goals. A thank-you page visit alone is not proof of a unique stored submission; reloads/direct visits can affect page-based tracking. Apply your existing consent settings.

SCHEMA AND ROLLBACK
No schema change and no migration required. All 48 migration files and all 24 Netlify function modules are byte-identical to v0.17.70. If rolling back, remove this new Footer redirect snippet or restore the prior website snippet as well: v0.17.70 assessment events occur before CV uploads complete.
