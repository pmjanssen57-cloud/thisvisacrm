THiS CRM v0.17.72 — 4 November 2026

INSTRUCTIONS STUDIO — ADVISER BLOCK BUILDER
Based on v0.17.71. The compulsory People / Introduction / Documents setup is replaced by a client-name and visa-category bar and one document editing workspace. Names and category populate the cover and starting introduction. The category supplies starting blocks for adviser review. The adviser switches between the introduction / road map, documentation guide and optional specialist guides from Working on.

Document sections provides the outline. Select a block to edit its heading and formatted wording directly; use headings, bold, italic, bullets, numbered lists, tables and callouts. Blocks can be moved up/down, duplicated, removed, re-added from the starting library or restored to their starting wording. Add block searches category starting blocks and the existing reusable guidance library. Write a custom block creates client-specific wording. There is no obligatory separate people or recipient form.

Family / people adds an optional document block. Add a partner, children or other people within it; linked client/family facts are available where supplied. Each document request has its own title, instructions and selection of people, so a passport request can cover the main applicant and partner while birth certificates are requested only for named children. Person removal clears their associations after a CRM-generated confirmation. Family edits remain in the instruction draft.

Police country guidance remains available within the Character block, with editable country wording, people and source links. Country snippets are existing starting material, not newly verified policy advice. New drafts resolve the police-instructions placeholder and print selected country guidance once even when the general Character wording is tailored.

New block-builder drafts print explicit sections and requests. Implicit legacy at-a-glance, next-three-steps and format/quality helper panels are suppressed in new drafts, so the adviser controls the document through the blocks they can see. Cover, page numbering, signoff and PDF layout still use the existing renderers. Saved older drafts retain their previous output and selections, including legacy helper panels.

Edit document, Edit & preview and Preview replace the wizard navigation. Output settings holds date, issue title, adviser, greeting, cover image and PDF arrangement. Include this guide in output controls the print set. Save to CRM, Print / save PDF and Mark ready use the existing persistence and review flows. Mobile uses a collapsible outline, stacked fields, readable entry text, comfortable buttons and viewport-fitting dialogs. Printing/help remain reachable through More on small screens. Studio Help has been rewritten for this workflow.

DRAFT INTEGRITY
Draft blocks are now merged by ID when reopened, avoiding unrelated positional defaults being applied after reorder, duplication or removal. Block state, person/document assignments and new builder metadata persist in the existing studioState JSON. Custom cover images have a separate persisted draft property because the existing CRM serializer strips master hero fields. Changing visa category asks for confirmation and replaces active category content with its starting blocks while retaining administrative client/family names; save first to retain the earlier draft as a CRM version.

SCHEMA / DEPLOYMENT
No migration required. No schema change. All 48 migration files and all 24 Netlify function modules are byte-identical to v0.17.71. New properties are stored within the existing instruction JSON field. The agreement engine is unchanged. Prior employer questionnaire handling, CRM work/client/task improvements and all five thank-you redirect mappings are preserved. No Squarespace embed or Footer changes are required for this release.

Deploy THiS-CRM-v0.17.72.zip through the normal Netlify build process: yarn build, publish dist. The ZIP contains deployable source and excludes node_modules and generated dist. New Instructions builder JS/CSS load after the existing Studio and people model; both are included in the v0.17.72 service-worker precache. Nothing deployed to production.
