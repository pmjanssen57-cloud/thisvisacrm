THiS CRM v0.15.12 - Netlify Efficiency Foundation

Baseline
- Built from v0.15.11 Unified Client Editor + Agreement Hotfixes.
- Retains the unified client editor, signed-agreement visibility, targeted agreement loading and corrected agreement PDF flow.

Netlify efficiency changes
- Routine intake/contact polling is now incremental. The CRM sends a server-issued cursor and receives only enquiries created or changed since the previous refresh.
- A manual Refresh remains a full reconciliation when explicitly requested.
- The delta cursor is captured server-side before each query so submissions arriving during a refresh are not missed.
- Added an index on intake_enquiries.updated_at to keep delta queries efficient as the enquiry table grows.
- Ordinary save operations no longer call readCrmData() and return the full practice dataset.
- Client-side state now merges targeted mutation responses for advisers, preferences, tasks, calendar entries, library items, intakes, instruction sets/templates, agreements/templates, email templates, seminars, feedback, booking records and commercial-client records.
- Bulk booking availability and blocked-time saves refresh only their relevant booking collections rather than the entire CRM.

Database
- Includes migration 202608110001_add_intake_updated_at_index.sql. It adds an index only; no data transformation is required.

No dependency or environment-variable changes.
